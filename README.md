# bili-live-stats

查询 B 站主播（虚拟主播 / VUP / VTuber / 普通主播）直播数据的命令行工具：每场流水、观看人数、弹幕数、互动数、付费人数、直播时长，以及单场收入构成（礼物 / SC / 舰长）与全站榜单。

零第三方依赖，只用 Python 标准库。

> ⚠️ **数据来源说明**：本项目不采集数据，只是查询 [danmakus.com](https://danmakus.com)（第三方监控站）的公开接口。数据非 B 站官方，覆盖范围取决于该站监控了哪些房间。使用前请阅读下方[免责声明](#免责声明)。

## 特性

- **场次级数据**：不是粉丝数这类宏观指标，而是每一场直播的流水、观看、弹幕、互动、时长
- **收入构成拆解**：单场流水可拆成礼物 / SC / 舰长三部分，与接口的 `totalIncome` 逐分对账
- **全站榜单**：流水榜、弹幕榜、场次榜、粉丝榜
- **零依赖**：`urllib` + `json`，装个 Python 就能跑
- **可机读**：所有命令支持 `--json`

## 命令

| 命令 | 说明 | 耗时 |
|---|---|---|
| `info <mid>` | 主播概览 | 2~5s |
| `lives <mid> [N]` | 最近 N 场（默认 20），支持 `--since` / `--until` | 2~5s |
| `live <liveId>` | 单场收入构成 + 打赏 Top10 | 20~30s |
| `rank [metric] [N]` | 全站榜单，metric = `income` / `danmaku` / `lives` / `fans` | 首次约 2min，之后 1~2s |
| `find <关键词>` | 按昵称搜 mid | 首次同上，之后 1~2s |

全局参数 `--json` 输出结构化结果。

### 示例

查最近 20 场：

```bash
python scripts/query.py lives 2132180406 20
```


## 数据口径

**流水** = `type` 为 1（礼物）、2（舰长）、3（SC）的 `price` 之和。

- `price` 已经是单条记录的总金额，**不要再乘 `count`**。`{"price":2,"count":20}` 表示 2 元买 20 个小花花，总额就是 2 元。乘了会让流水虚高。
- 该口径与接口返回的 `totalIncome` 完全一致，脚本内置对账，差异超过 0.01 元会提示。

**人均弹幕** = `danmakusCount / interactionCount`（对齐 laplace.live 的口径）。

**时长** = `(stopDate - startDate) / 1000` 秒。同一主播同一天可能有多场，按 `startDate` 区分。

## 已知的接口缺陷

实现过程中踩到的坑，记录下来以免重复：

1. **分页会丢数据**。`/live` 接口声称 `total=535`，但分页最多只能取到 303 条唯一记录，页内还有重复。因此统计流水**必须全量拉取**（不传 `pageSize`），本项目按此实现。
2. **`type=2` 筛选失效**。传 `type=2` 返回 `total=0`，筛不出舰长记录。只能全量拉取后本地过滤。
3. **`pageSize` 上限约 200**。传 500 会异常返回 35 条。
4. **域名会重定向**。`danmakus.com/api/v2/*` 302 跳到 `ukamnads.icu`，普通 HTTP 客户端跟随即可。

## 限制

- **覆盖不全**：仅包含被该站监控 / 投稿收录的频道。查不到不代表主播没播过，新主播、小主播大概率缺失。
- **非实时**：统计有数小时到一天的延迟。
- **首次榜单慢**：`rank` / `find` 需下载 27MB 全站快照，缓存到 `~/.cache/bili-live-stats/`（24 小时有效）。
- **接口无 SLA**：第三方站没有文档和承诺，随时可能变更或失效。
